# Corpus and comparer

How the app reads the corpus and compares versions of a law or a collection. Source paths (`routes/`, `components/`, `lib/`, `styles/`, `server/`, `app.tsx`, `document.tsx`) are under `web/src/`; other paths are relative to `web/`.

## The corpus and the comparer

The pipeline writes it and this app only reads it: `uv run hukum-rapih export-corpus --publish <dir> --public ../web/public` (in `pipeline/`, code in `src/hukum_rapih/corpus/`), read in dev through `HUKUM_CORPUS_DIR` (see `README.md`). A new or changed field in a published record is two edits: the Python writer and the valibot schema in `server/records/` (`lib/pair-records.ts` for the comparison files, which the browser parses too). No diff runs here: the law page and the collection page share one comparer (decision 0017). The address is `?v=a,b,c`, one column per version (one id stands for it against the version before; empty for first against latest). A visit to an address is rendered on the server: `server/comparison.ts` reads `collections/<slug>/comparisons/` (`server/records/collection-comparison.ts`, written by `corpus/version_comparison.py`, which writes only older-to-newer pairs) for each pair of neighbouring columns, always older version first (`neighbourPairs`), and `lib/compare.ts` maps the published lines to rows of cells, pairing lines by number. A change made on the page does not call the server: `lib/browser-comparison.ts` fetches the same files from `/data/<release>/collections/<slug>/comparisons/` (`server/middleware/release-data.ts` streams the corpus object, immutable, never parsed; the path is `comparisonFilePath` in `lib/schemas.ts`), parses them with the schemas in `lib/pair-records.ts` and maps them with the same `compareColumns`. The release comes with the comparison the page shows (`PublishedComparison.release`, noted by `noteShown` in the page's memo, which is how a hydrated page learns it), a failed file leaves the comparison on screen with `failed` set and `components/comparison-failure.tsx` offers a retry (decision 0018). The law page reads its record and its comparison in two memos (`lib/law-page.ts`) so a change of versions never reads the law again. The law page places those rows in its text (`placeInText`, `components/law-text.tsx`); the collection page lists them (`components/collection-compare.tsx`); both draw a row with `PasalBlock` (`components/compare-block.tsx`) and choose versions in `CompareBar` (`components/compare-bar.tsx`). No per-collection record is needed, and every control is a link or a field of one GET form, so it works without JavaScript. The comparer marks itself with `data-cmp-bar`, which the layout reads to widen the text and fold the panel; the draft synopsis (`routes/draft-comparison.tsx`) pairs by content and stays its own view. Labels, display helpers and the search query reader live in `lib/` (`labels.ts`, `display.ts`, `search-query.ts`). `scripts/` holds `route-snapshot.sh`.
